# AgentSmith Data Model

All documents carry a numeric `version`. Resource files are modular so a damaged goal does not prevent projects or providers from loading. IDs are stable, lowercase-kebab identifiers generated by the application for new resources.

## Configuration Root

```text
~/.config/AgentSmith/
├── config.json
├── projects.json
├── profiles.json
├── goals/<goal-id>.json
├── roles/<role-id>.json
├── guardrails/<profile-id>.json
├── providers/providers.json
├── providers/instructions.json
├── instructions/global.md
├── prompts/templates.json
└── logs/
```

On Windows the root is `%APPDATA%/AgentSmith`. The configured path is displayed in Settings.

## `config.json`

```json
{
  "version": 1,
  "locale": "en",
  "theme": "dark",
  "showHiddenFiles": false,
  "lastProjectId": null,
  "activeProfileId": "default-agent"
}
```

Unknown fields are retained during saves. Secrets are intentionally not represented.

## `projects.json`

```json
{
  "version": 1,
  "projects": [
    {
      "id": "project-uuid",
      "name": "Example project",
      "path": "/Users/example/Code/example",
      "lastOpenedAt": "2026-10-02T09:00:00.000Z"
    }
  ]
}
```

The path is revalidated on every open. Removing a registration never removes project files.

## Goals, Roles, and Guardrails

Goals and roles contain `id`, `name`, `description`, `instructions`, `enabled`, and optional tags/order. Guardrail profiles contain a `rules` array:

```json
{
  "version": 1,
  "id": "default-security",
  "name": "Default Security",
  "rules": [
    {
      "id": "deny-env",
      "type": "file_access",
      "pattern": "**/.env*",
      "action": "deny",
      "enabled": true,
      "enforcement": "application"
    }
  ]
}
```

`enforcement` is `prompt`, `application`, `provider`, or `advisory`; it prevents the UI from implying that prompt text is a hard security boundary.

## Providers and Profiles

Provider configuration contains IDs and display preferences only. Installation and model discovery are runtime facts and are not treated as persisted truth. Agent profiles reference provider, model, variant, role, goals, and guardrail IDs; missing references are shown as unresolved instead of silently substituted.

Provider-specific instruction text is stored separately in `providers/instructions.json` as a versioned map keyed by provider ID. It is optional, contains no credentials, and is an AgentSmith-managed source rather than an assumption about a provider's global filesystem location.

## Prompt Model

The composer returns:

```ts
{
  text: string;
  sections: Array<{ id: string; title: string; content: string; included: boolean }>;
  blockedContexts: Array<{ path: string; reason: string }>;
}
```

The input supports independent toggles for global/provider/project/nested instructions, Git status/diff, project structure, `README.md`, `composer.json`, `package.json`, and Explorer-selected files. The rendered preview and execution request consume this same object. No second illustrative prompt format exists.

## Migration Strategy

The store checks versions on load. Version-zero documents are migrated in memory, a backup is written before the migrated document replaces the original, and the migrated version is then saved atomically. Unknown future versions are left untouched and surfaced as a warning instead of being overwritten. Envelope fields not owned by AgentSmith are retained during collection saves.
